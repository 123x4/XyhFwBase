# Lina H6 原始采样与 CRC

校频和 32 项启动配置沿用原流程。配置读回全部通过、USB 配置完成后，启动先打印一次 `H6_CFG`、再打印一次 `H6_CAL`，随后每 100 ms 读一次两颗 H6 的最新转换结果。采样路径只发 `HAL_CONVERT` 脉冲和四个全零时钟字节。校频失败或读回持续不符时，USB 仍输出启动诊断，跳过 RAW。 [采样实现](../app/button.c#L1127) · [诊断循环](../app/button.c#L1184)

## 帧与波形

| 项目 | 本轮参数与判读 |
| --- | --- |
| td1 高电平 | 给现有脉冲函数传 `3U`，预期约 5.0 µs，手册窗 4.75–5.25 µs。 |
| td2 低等待 | 传 `26U`，预期约 28.8 µs。手册连续转换下限为 >4 µs，本次台架检查 >24 µs。 |
| SCK 短时钟 | 一次 SSP 收发 4 字节，共 32 个短时钟。前半字标记 R（H2），后半字标记 L（H1）。用分别按键实测确认物理映射。 |
| 14 位有效值 | 日志 R、L 显示完整 16 位帧。对每个字取 `word & 0x3FFF` 得到 ADC 值。CRC1/CRC0 是最高两位。 |
| `crc` | 3 表示两颗都通过，1 仅 R 通过，2 仅 L 通过，0 表示两颗均失败。 |

0x33=0x80 时芯片内部连续转换，100 ms 是 MCU 诊断读取节奏。ADC 上限为 16383，判饱和时先看 CRC 再看掩码后的值。例如完整帧 `0xFFFF` 对应通过奇偶校验的满量程 16383，而 `0x3FFF` 和 `0xC000` 与各自数据的校验位不匹配。量跨度时优先选 `crc=3` 的稳定行。 [GTRY164 帧格式 p8](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=8) · [td1/td2 p12](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=12) · [连续模式 p20](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=20)

## Windows 台架

1. 解压刷新后的测试包，用 Keil 重建 `Sample.uvproj` 的 `Target 1`，烧录本次生成的 `output/Sample.hex`。 [Windows 测试包](Lina-H6-校频诊断-Windows.zip)
2. 在解压后含 `tools` 的目录运行 `python .\tools\h6_usb_log.py`，看到等待提示后接上板。这里省略 `--once`，因为该参数收到 `H6_CAL` 就退出。启动预期为 `H6_CFG n=32 miss=0`、`H6_CAL PASS ...`、周期性的 `H6_RAW R=0x.... L=0x.... crc=3`。 [日志脚本](../tools/h6_usb_log.py#L31)
3. 两键都松开、仅左键压到底、仅右键压到底，每种状态保持 3–5 秒，各保留 3–5 行。比较按下前后掩码后的值，确认变化方向和跨度 `|bottom - top|`，再看松开后是否回到原值附近。需要判单调性时，缓慢压下或缓慢松开，让 100 ms 日志覆盖中间行程。
4. 若抓波形，用 CH1 接 `SCLK_0`，在 80 MS/s 下把高脉宽触发设为 3–10 µs。确认 td1 4.75–5.25 µs、下降沿到第一个短时钟 >24 µs、随后 32 个短时钟。有一路空闲且 CRC 持续不通过时，可把第二通道接 MISO。回传三组日志、观察到的方向和采样 CSV（如有）。

本地完成 Cortex-M0 Clang 单文件编译、12 个旧版型的预处理对比，以及覆盖全部 16384 个 ADC 码与四种 CRC 状态的模拟。也模拟了配置读回失败、启动日志只打印一次和跨计时器回绕的 100 ms 节奏。Keil 整工程构建和实板 td1/td2、方向及跨度待验证。
