一、为什么改成全写

之前的方案是“只写必需的 9 项、其余靠上电默认”。改成全写，理由有四条。
1. 不依赖上电默认。默认值是硅片的“出厂态”，不同批次、不同复位路径未必一致； 显式写一遍，上电状态就完全由固件决定，可复现、可回滚。
2. 与 XENO 同项数 = 同一条已验证路径。XENO 是在真实产品上跑通的配置；项数一致， 就排除了“漏写某个寄存器导致行为不同”的可能，出了问题也更容易和 XENO 对比。
3. 读回验证覆盖完整。32 项都能读回（我们已实测 WR 寄存器可读回影子值）， 一旦某项没写进去，立刻能从读回值发现，而不是等采样异常再倒推。
4. 代价要说清：8 个手册未公开的寄存器（0x13/0x15/0x16/0x18/0x1C/0x1E/0x20/0x25） 也跟着 XENO 写。它们没有位定义，写错不知道后果——所以第一轮一旦出现异常， 优先怀疑这 8 个，回退方法就是恢复成上电默认（或整组去掉重测）。

五、10 项差异逐条说清

① 采样间隔 28 → 124 µs

0x0F：0x07 → 0x1F
应用差异
  • XENO 键盘要 32 kHz 上报；Lina 1 kHz 轮询，124 µs 已 8 倍富余
  • 间隔越短功耗越高

② 按下方向 0x41 → 0x01

0x32 bit6：1 → 0
应用差异，待实测复核
  • 磁铁方向相反
  • H5 固件 16383−raw 说明按下原始值变小

③ 硬件 baseline 0x84 → 0x80

0x33 bit2：1 → 0
最关键的一处
  • XENO 产测注释：开 baseline 输出 0–8000 相对值，关着是 8000–16000 原始值
  • Lina 上层吃原始值，开了等于推翻软件基线/RT

④ LED 电流：白平衡值 → 0

0x05–0x08
应用差异
  • Lina 霍尔 LED 引脚未接
  • 显式写 0，不依赖默认

⑤ LED Imax：0x25 → 0x20

0x09 低 4 位：5 → 0
应用差异
  • Imax 2.4 mA → 0；bit5 两边都是 1，LNA 选择不受影响

⑥ 基线初值：产线值 → 8192

0x2D/0x2E
应用差异
  • XENO 用每颗键的产线 flash 值或自动填充
  • 我们 baseline 关闭，写中点 8192 即可，保证寄存器状态确定
其余 22 项（含 8 个未公开寄存器、0x1B/0x2B/0x2C 中断参数、固定值组）数值与 XENO 完全一致， 都是显式写入，不再依赖上电默认。
