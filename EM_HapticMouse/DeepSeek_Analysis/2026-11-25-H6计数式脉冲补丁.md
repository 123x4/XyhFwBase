# H6 计数式脉冲补丁（草案）

补丁文件：[H6-pulse-counts.patch](H6-pulse-counts.patch)（针对当前工作区 `app/button.c`，含 Codex 10:2x 的 `DELAY_OUT(128)` 改动）。本轮只出草案、不落地到 `app/button.c`，等 Codex 应用或分派。

## 1. 为什么不是“126 + NOP 补偿”

- 现有映射：实测脉宽 ≈ 传入值 + 1.26 µs；126 会落在 127.26，要补 0.74 µs ≈ 35–36 个 NOP。
- NOP 必须字面展开（循环每轮多 3–4 拍），且每次周边代码变化都要重新标定；收益只有 0.26 µs。
- 更关键：**td1 用整数微秒根本无解**。`CT16B1_DelayUs()` 步进 1 µs，而 td1 窗口只有 4.75–5.25；传 3 → 4.26，传 4 → 5.26，两头都在窗外。
- 计数式一次解决 td10/td6/td1：1 拍 = 20.83 ns，一个固定偏置常量对所有脉宽通用。

## 2. 补丁做了什么

| 位置 | 改动 |
| --- | --- |
| `app/button.c` 新增 `Hall_H6_PulseUs()`（仅 `GT_LINA_T1A_H6_PWM`） | CT16B1 用 48 MHz（PR=0）计数，GPIO SET 后读 `TC` 作起点，轮询到 `counts` 再 CLR；高电平期间用 PRIMASK 全屏蔽，低电平用原 `CT16B1_DelayUs()` |
| `Hall_CLK_Command_SET()` 的 Lina 分支 | H6 时调用新函数，H5 原代码一行不动（缩进也不动，减少 diff） |
| 删除 `H6_SCK_HIGH_TRIM_ONE_CYCLE` 的 `__NOP()` | 被 `H6_PULSE_TRIM_COUNTS` 取代 |
| 诊断调用 | `DELAY_OUT(128)` → `128U`（计数式下按标称微秒传，不再依赖 +1.26 µs 的巧合） |

关键常量：

```c
#define H6_PULSE_COUNTS_PER_US  48      /* 48 MHz */
#define H6_PULSE_MAX_COUNTS     65500   /* 16 位 TC，留余量 */
#define H6_PULSE_TRIM_COUNTS    0       /* 唯一的标定常量，负值缩短 */
```

`counts = highUs * 48 + H6_PULSE_TRIM_COUNTS`，因此**同一个 trim 对 128 µs 和 5 µs 都成立**（固定偏置，不随脉宽变化）。

## 3. 应用方式

```bash
cd EM_HapticMouse
patch -p1 --dry-run -i DeepSeek_Analysis/H6-pulse-counts.patch   # 先干跑
patch -p1 -i DeepSeek_Analysis/H6-pulse-counts.patch
```

已在独立副本上跑通 `--dry-run` 和实际应用，并用 `cpp` 对比过两种板型的预处理输出：H5 分支忽略空白后与改前**完全一致**，H6 分支只剩新函数调用（无 `DrvGPIOOutput(1,15,1)`、无 `__NOP`）。

## 4. 标定步骤

1. 应用补丁，Keil 重建、烧录（`my_board.h` 保持 H6）。
2. Saleae 设置不变：CH1 接 `SCLK_0`，80 MS/s、1–2 s、高脉宽触发 80–200 µs，先 Start 再上电，导出整组 CSV。
3. 用 [h6_sclk_analyze.py](h6_sclk_analyze.py) 算均值：

```bash
python3 DeepSeek_Analysis/h6_sclk_analyze.py <新的.csv>
```

4. 按实测均值算 trim 并写回：

```
trim = round((128.00 − 实测均值µs) × 48)
```

例：均值 128.17 → trim = round(−8.16) = **−8**；均值 127.9 → trim = +5。
5. 重建、复测。判据：均值 128.00 ±0.10、极差 ≤0.2 µs、低等待 >50、每条 32 时钟。

预期：trim=0 时约 **128.1–128.2 µs**（GPIO SET 到读 TC 约 2–3 拍、轮询退出约 3–5 拍）。若实测明显偏离这个预测，先查中断是否真的被屏蔽（高脉冲不该再出现 +2.3 µs 的跳变）。

## 5. 与 H5 的关系

- H5 和其他版型：`Hall_H6_PulseUs()` 不参与编译，`Hall_CLK_Command_SET()` 的 H5 分支预处理输出不变（忽略空行），行为零变化。
- CT16B1 本来就是共享延时定时器（`CT16B1_DelayUs()` 每次都会重设 PR/TC/MCR），新函数同样在返回前停表，不改变这一约定。
- 新函数只在**高电平期间**关中断：td10 关 128 µs，td1 只关 5 µs（1 kHz 采样下约 0.5% 占用）。低等待保持可中断，所以 62.6/64.9 µs 那种 +2.3 µs 的跳动还会出现，对 td12（只有下限）无害。

## 6. 后续采样要一起改的点

H6 走通采样时，`hall_get_sample()` 之类会传给同一个函数，参数必须是**标称微秒**：

| 事务 | 传参（H6） | counts（trim=0） |
| --- | --- | --- |
| td1 转换 | 5 | 240 |
| td2 连续等待 | 6 | 低电平，仍走 `DelayUs` |
| td6 读写 | 39 | 1872 |
| td10 校频 | 128 | 6144 |

也就是说 H6 版型不能再用 `TD1_DELAY_US = DELAY_OUT(5)` 这类 H5 宏；要么给 H6 单独一组标称宏，要么在调用处直接传常数。
