# H6 脉冲改回 H5 延时 + 尾部补一段延时

补丁：[H6-pulse-tail-after-delay.patch](H6-pulse-tail-after-delay.patch)。按“在 H5 的 delay 后面直接加一个延时”实现，删掉计数式函数。未改工作区源码。

## 1. 改法

- 删除 `Hall_H6_PulseUs()` 与 `H6_PULSE_*` 三个常量，`Hall_CLK_Command_SET()` 的 Lina 分支恢复为唯一一条 H5 实现（H6 与 H5 共用）。
- 在 `CT16B1_DelayUs(high_delay)` 之后、`DrvGPIOOutput(1,15,0)` 之前，插入 H6 专用的尾部延时：

```c
	//nsAPI_SSP_DelayUs(high_delay);
	CT16B1_DelayUs(high_delay);

#if defined(GT_LINA_T1A_H6_PWM)
	H6_PULSE_TAIL();          /* 36 个 __NOP__，每拍 20.83 ns，共 750 ns */
#endif

	DrvGPIOOutput(1,15,0) ;
```

- `H6_PULSE_TAIL()` 用 `1/2/4/8/16/32` 逐级组合，当前是 `32 + 4 = 36` 拍；要微调就给这一行加/减整拍。
- 校频调用由 `128U` 改为 **`126U`**（低等待仍是 60）。
- H6 专用地给高电平加了 `PRIMASK` 临界区：拉高前保存并关中断，拉低后恢复；H5 构建里这些块整体编译掉。

## 2. 数值依据

上一轮 `CT16B1_DelayUs` 版实测（10:42 采集）：传 127 → 均值 128.2638，即 **实测 ≈ 传入 + 1.26 µs**。

| 项 | 数值 |
| --- | ---: |
| 传 126 µs | ≈ 127.264 |
| + 36 NOP | +0.750 |
| 合计 | **≈ 128.014** |

微调分辨率 20.83 ns/拍，比 80 MS/s 采集的 12.5 ns 略粗，够用。若首测偏离，只改 `H6_PULSE_TAIL()` 这一行的组合即可，不用动其它常量。

## 3. 验证

- `patch -p1 --dry-run` 与实际应用通过，`git apply --check` 通过（在 `EM_HapticMouse/` 下）。
- `cpp` 展开：**H5 分支忽略空行后与改前完全一致**；H6 分支共 36 个 NOP，已无 `Hall_H6_PulseUs` 引用；括号配平。
- 未做 ARMCC 编译（本机无工具链）。

## 4. 中断屏蔽已处理

H5 这条路径原本只关 `USB_IRQn`，1 ms 定时器中断仍可能落进高电平窗口，把 128 µs 拉长 ~2.3 µs。对 td10 无害（130.3 仍在 121.6–134.4 内），但会毁掉将来的 td1（5 µs ±0.25）。

本次直接加上 H6 专用的 `PRIMASK` 临界区：

```c
#if defined(GT_LINA_T1A_H6_PWM)
	primask = __get_PRIMASK();
	__disable_irq();
#endif
	DrvGPIOOutput(1,15,1) ;
	CT16B1_DelayUs(high_delay);
#if defined(GT_LINA_T1A_H6_PWM)
	H6_PULSE_TAIL();
#endif
	DrvGPIOOutput(1,15,0) ;
#if defined(GT_LINA_T1A_H6_PWM)
	__set_PRIMASK(primask);
#endif
```

临界区只覆盖高电平（128 µs），低等待仍可中断；H5 构建中这些块整体编译掉，行为不变。代价是校频期间每条脉冲会推迟一次 tick（最多 128 µs，16 条合计约 2 ms），只发生在上电初始化阶段。
