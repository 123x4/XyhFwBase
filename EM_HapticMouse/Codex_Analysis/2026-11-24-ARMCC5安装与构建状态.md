# ARMCC 5 安装与构建状态

工程 `Sample.uvproj` 的 `Target 1` 指定 Arm Compiler 5.06 update 7（build 960）。Arm 的官方发行说明指定下载修订号 `r5p6-07rel0`，用于 MDK v5 的已确认发行包是 Win32 版。Arm Product Download Hub 需要登录 Arm 账号才显示版本下拉列表。当前 Linux 环境可以打开下载门户，尚无已授权的工具链安装包、可用的 ARMCC 授权配置或可访问的 Windows Keil 构建机。另验证了旧版 MDK 安装器能从 Keil 站点读取，但它是 Windows 安装器。尚未安装指定编译器，尚未生成本次 HEX 或 AXF。 [Arm 下载索引](https://support.arm.com/documentation/ka005198/1-0/?lang=en) · [MDK 发行说明](https://documentation-service.arm.com/static/688c9f3e954a4878bb154f2c%3Ftoken%3D) · [ACOMP5 下载入口](https://support.arm.com/downloads/view/ACOMP5)

继续构建需要可访问的、已配置该版本的授权构建环境，或者可在此环境运行的官方安装包与相应授权。现有 Windows Keil 若已装好 build 960，可按以下命令重建。

```powershell
& 'C:\Keil_v5\UV4\UV4.exe' -r '.\Sample.uvproj' -t 'Target 1' -o 'build-armcc5.log'
```

`C:\Keil_v5` 需按实机安装位置调整。构建时核对日志中的编译器版本和错误摘要，随后核对 HEX、AXF 的生成时间。本轮重新检查时，`Device_Init` 的调用、声明和实现已经一致，上次发现的符号不匹配已消失。已有 MAP 的 ROM 总量约 44.64 KiB，超过 Keil 官方文档列出的 MDK-Lite 32 KiB 上限，正式构建应使用适用于此工程的授权。工作区源码和旧构建产物均未改动。 [调用](../src/Main.c#L16) · [实现](../src/device.c#L273)

容量依据为 [历史 MAP](../List/Sample.map#L1787) 和 [Keil 评估版限制](https://www.keil.com/demo/limits.asp?bhcp=1)。
