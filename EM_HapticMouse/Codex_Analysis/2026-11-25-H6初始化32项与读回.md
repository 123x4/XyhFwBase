# Lina H6 初始化 32 项与读回验证

H6 校频两颗都通过后，按附件顺序向两颗 H6 写入 **32 项**。末项 `0x33=0x80` 开启连续转换，保持芯片中断和硬件 TOP 基线关闭。调用现有 `TimerDelayMsec(1U)` 后开始寄存器读回。保留校频 126U/60U、最多 128 次、首次通过退出和循环后的 20 ms 等待。寄存器脉冲用已有 37U/4U，沿用 31 拍 NOP 和 PRIMASK 段。固件这一步没有发 ADC 采样命令。 [配置表](../app/button.c#L1005) · [H6 诊断流程](../app/button.c#L1126)

- 写帧的 bit15 为 1，bit14 为 6 位地址与 8 位数据的异或。两颗写同一配置时，前后 16 位发送同一帧。读回比较两个 16 位字各自的低字节。 [GTRY164 V1.9 p9–10](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=9)
- 0x13、0x15、0x16、0x18、0x1C、0x1E、0x20、0x25 沿用附件指定的 XENO 常规配置值。其位义和回读特性仍待确认，目前与公开寄存器同样按原值逐字节比较。 [XENO `h6_hal_type_mode`](../Materials/GT_SS_XENO_APP_20260916/src/h6/h6_hal.c#L1219)
- 第一次不符只重读同一地址一次，因而 0x33 保持最后一笔写入。仍不符就停止读后续地址，记录两颗返回值并进入现有 USB 循环。`n` 计已检查的地址数，包含最后一个失败地址，`miss` 为 0 或 1。 [读回实现](../app/button.c#L1104)

## 本地验证

Clang 编译了 `app/button.c` 的 Cortex-M0 目标文件。12 个非 H6 版型的该编译单元预处理输出与改前一致。模拟核对了 64 个地址乘 256 个数据值的写 CRC、32 项写入和读回顺序、一次重读后通过、首项或末项持续不符、以及校频失败时跳过配置。Windows 测试包已更新并确认包内 `app/button.c` 与工作区字节一致。此环境没有 Windows Keil ARMCC build 960 或 Lina 测试板，整工程编译、烧录、真实回读和波形仍待台架验证。 [Windows 测试包](Lina-H6-校频诊断-Windows.zip)

## 上板验收

1. 解压最新测试包，用 Keil 打开 `Sample.uvproj`，重建 `Target 1`。确认 **0 Error(s)** 后烧录新生成的 `output/Sample.hex`。
2. 运行 `py tools/h6_usb_log.py --once` 并冷启动。正常应先看到 `H6_CFG n=32 miss=0`，再看到 `H6_CAL PASS ...`。成功表示两颗的 32 项都已比较，包含 0x0C=0x83、0x32=0x01、0x0B=0x88。若有 `H6_CFG_ERR`，保留错误行和汇总。`H6_CAL PASS` 仅表示校频成功。
3. CH1 接 `SCLK_0`，80 MS/s，高脉宽触发 20–60 µs，先 Start 再上电。全程一次通过预期有 32 条写命令和 32 条读命令，目标高宽约 **39.16–39.18 µs**。写事务在 td6 前有 32 个短时钟，读事务在 td6 前后各有 32 个。若某地址触发重读，波形会多一次该地址的读事务。需要独立抽查回读值时，可把第二通道接 `MISO_0`，核对读回阶段的第 2、4 字节。
4. 回传 CSV、`H6_CFG` 和 `H6_CAL`，以及出现时的 `H6_CFG_ERR`。读回不符时先定位失败地址。台架通过后再清理一次性验证，保留配置及查询函数。
