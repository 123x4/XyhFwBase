# 0x35 读回实测通过

数据：`untitled.csv`（31,856 字节，`sha256 0350524b…`）+ USB 日志截图。固件为 Codex 14:11 的 0x35 读回版（31 拍尾部，`Hall_CLK_Command_SET(37U, 4U)`）。只分析，未改代码。

## 1. USB 结果

```
H6_REG35 R=0x27 L=0x27 R2=0x27 L2=0x27 R3=0x27 L3=0x27
H6_CAL PASS n=16 w0=0x0082 w1=0x0083
```

- `0x35`（SDO_Drive_Current）上电默认就是 **0x27**，三次读、两颗芯片**全部读对**，且三次一致 → 读事务、地址字段、链上转发都正常。
- 校频仍 `PASS n=16`，两个低字节 0x82/0x83 在窗口内。

## 2. 波形

**16 条校频脉冲**：全部 **128.0000 µs**，极差 0.0000（80 MS/s 下完全一致），比上一组的 127.9992 更整齐。

**3 条 td6 命令（39 µs）**：

| # | 高宽 µs | 下降沿→首时钟 | 请求时钟 | 回读时钟 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 39.18 | 6.81 µs | 32 | 32 |
| 2 | 39.18 | 6.81 µs | 32 | 32 |
| 3 | 39.17 | 6.81 µs | 32 | 32 |

判据：td6 37.05–40.95 ✓（偏高 0.18，占窗口 4.6%）、td5 >3 ✓（6.81）、每段 32 clocks ✓、组内 0.5000 µs ✓。

结构也符合图 7：**32 clocks 装请求 → 39 µs 高脉冲 → 6.8 µs 低等待 → 32 clocks 回读**；两次读之间回读末时钟到下一次请求首时钟的间隔约 3.5 µs。

## 3. 判定

**阶段 2（寄存器读）通过。** 读命令、35 µs 级时序、地址帧、双芯片回读都被实测覆盖。

仍未覆盖：
1. **代码半区与芯片的对应**——物理左右由原理图确定（H1 标注 `LB` 是左键，H2 标注 `RB`
   是右键，链路 MCU→H1→H2→MISO），尚未实测的是 `tx[0..1]` 是否真的到 H2、
   `rx[0..1]` 是否真的来自 H2。两颗 `0x27` 相同，读同一个默认值分辨不出来。
2. **写路径**——含地址的 `CRC_WR` 差异还没测。

## 4. 下一步：写 0x07 验证写路径与半区映射

用 `0x07`（LED3 电流，默认 0x00；Lina 的霍尔 LED 引脚未接，改它无副作用）。选它而不是 0x05，
是因为 0x07 的 6 位地址有 3 个 1（奇校验），`CRC_WR` 会与"只算数据位"的旧规则不同，
能真正验证地址位参与了校验。

写帧（图 6）：`bit15=1`、`bit14=CRC_WR`、`bits13:8=addr`、`bits7:0=data`，
`CRC_WR = A5^A4^A3^A2^A1^A0^D7^…^D0`。

| 目标 | 地址奇偶 | data | 数据奇偶 | CRC_WR | 首字节 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 右（假定 H2） | 1 | 0x11 | 0 | 1 | 0xC7 |
| 左（假定 H1） | 1 | 0x2A | 1 | 0 | 0x87 |

序列（每段命令都用 `Hall_CLK_Command_SET(37U, 4U)`，即 td6≈39 µs）：

```c
tx[0]=0xC7; tx[1]=0x11; tx[2]=0x87; tx[3]=0x2A;   /* 写互异值 */
SSP_Send_Receive(tx, rx, 4);  Hall_CLK_Command_SET(37U, 4U);
tx[0]=0x07; tx[1]=0x00; tx[2]=0x07; tx[3]=0x00;   /* 读回 0x07 */
SSP; pulse; SSP;  -> rx[1], rx[3]
tx[0]=0xC7; tx[1]=0x00; tx[2]=0xC7; tx[3]=0x00;   /* 恢复默认 0x00 */
SSP_Send_Receive(tx, rx, 4);  Hall_CLK_Command_SET(37U, 4U);
/* 再读一次确认恢复为 0x00 */
```

判读：

- `rx[1]=0x11, rx[3]=0x2A` → 写生效（含地址 CRC），且半区自洽；结合链路末级是 H2，
  前半即 H2/右键；
- 两个值对调 → 写生效但半区映射与假设相反，后续按芯片分半的读写都要翻转；
- 全 `0x00`/`0xFF` → 写未生效。先看 MOSI 上四个字节是否正是 `C7 11 87 2A`、
  td6 是否落在 37.05–40.95，再查 CRC 公式与 bit14 位置；
- 恢复后读不回 `0x00` → 第二次写有问题。

物理左右不需要在这一步判定：原理图已确定 H1（`LB`）=左、H2（`RB`）=右，链路是
MCU→H1→H2→MISO；这里验证的是**代码半区与芯片的对应**，物理正确性留给采样阶段
按"按左键看哪半变化"复核一次。

## 5. 顺带建议

- 读回日志可以加 16 位原始值（`rx[0]`/`rx[2]`），这次三次一致说明帧没歪；加上高位能让以后定位更快。
- 本次 td6 39.18 比标称高 0.18 µs，无需调整（窗口 ±1.95）。若要压到 39.00，可把 td6 的传值改 36（→ 38.2），但那样反而偏离更多；保持 37 即可。
