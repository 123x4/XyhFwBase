# Lina H6 校频诊断与 USB 日志

[Windows 测试包](Lina-H6-校频诊断-Windows.zip) 包含原有 `Sample.uvproj`、固件源码和 USB 日志工具。板型在 `inc/my_board.h` 中切换，压缩包和仓库默认均选 Lina H5。

## 1. 编译并烧录 H6 诊断固件

1. 在 Windows 解压测试包，在 `EM_HapticMouse/inc/my_board.h` 注释 `GT_LINA_T1A_H5_PWM`，取消注释 `GT_LINA_T1A_H6_PWM`。H6 版型目前执行校频诊断。
2. 打开 `EM_HapticMouse\Sample.uvproj`，用 ARMCC **5.06 update 7 (build 960)** 重建 **Target 1**。成功后检查 `output\Sample.hex` 是本次生成，建议另存为 `Lina_H6_Clock_Diag.hex` 标明板型。
3. 按已有应用烧录方式，将本次重建的诊断 HEX 烧到 H6 板。应用区从 **0x4000** 开始，若用调试器烧录就用应用扇区擦除，保留 Bootloader 区。

## 2. 接收 USB 日志

在解压后含工程文件的目录打开 Windows PowerShell。首次运行安装 `hidapi`。

```powershell
py -m pip install hidapi
py .\tools\h6_usb_log.py --once
```

去掉 `--once` 会持续打印，按 Ctrl+C 停止。工具只打开设备 **1A81:2071** 的厂商 HID 接口（Usage Page **0xFF01**，Usage **0x01**），读取固件原有 `InfoLog` 的 EP3 IN 报告。固件在 USB 配置完成后约每秒重发同一次校频的结果，晚打开工具仍能看到。若同时有多个同型号设备，先只接当前测试板。[HIDAPI Python 绑定](https://pypi.org/project/hidapi/) · [USB 描述符](../src/usbdesc.c#L169) · [日志接口](../inc/my_debug.h)

示例日志：

```text
[I]Hall_H6_Diagnostic: H6_CAL PASS n=1 w0=0x007E w1=0x0082
```

`n` 是尝试次数，`w0/w1` 是链路顺序的两个原始 16 位字。手册 §7.6 规定低 8 位有效，§9.1 校频通过范围为 **0x7C–0x84**，只有同一次的两个字都通过才打印 `PASS`，并在成功后等待 20 ms。若用完 128 次仍未同时通过，打印 `FAIL` 和最后一次回读。左右键字序等后续寄存器或按压测试确认。该诊断路径仅运行校频和 USB 日志，暂停常规霍尔寄存器写入、采样与鼠标任务。[校频实现](../app/button.c) · [诊断入口](../app/button.c#L954)

## 3. 复测 SCLK_0

保持 CH1 接 `SCLK_0`，CH15 空着。用之前的 80–200 µs 高脉宽触发，80 MS/s。先开始采集再重上电。测命令高宽在 **121.6–134.4 µs** 内，下降沿到首个短时钟的低电平 **大于 50 µs**，然后有 **32 个短时钟**。低电平设定目标为约 60 µs，以上板实测为准。请回传 SCK 波形 CSV 及一行 `H6_CAL` 日志。[H6 时序表](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=12)

## 已验证的范围

- 用 Clang 预处理比较 12 个现有板型配置，在 5 个相关编译单元上忽略空白后结果一致。切换到 H6 版型后会启用 USB 日志、SSP1 和校频诊断，同时选中 H5 与 H6 会报错。
- 用模拟 SPI 测试了两个有效字、范围边界、失败重试与日志返回。用模拟 HID 测试了厂商接口选择、分包、零填充和命令行打印。
- Linux 工作区没有 ARMCC 5，未生成或烧录诊断 HEX。Windows 实际构建和硬件 USB 日志由本次台架测量验证。
