一、先建立直觉：一颗霍尔芯片在配什么

把 H6 想成一条流水线：磁铁靠近 → 模拟信号 → 数字值 → 判按键 → 送到 MCU。配置就是调每一站的旋钮。

我们只动前两站的少部分 + 一个固定值：模拟前端的 LNA/PGA、采样节拍、按键方向，以及必须改的 0x0C。第四站（硬件基线）建议保持关闭——Lina 的基线跟踪和 Rapid Trigger 都在 MCU 固件里， 芯片再叠一层会改变返回值的语义。

二、默认值陷阱：只有一个是“默认就错”的

0x0C（Test_Reg0）上电默认 0xAA，手册要求写 0x83。 这是全部配置里唯一一个“默认值与要求值不一致”的寄存器。漏写它，芯片在未定义状态下工作， 表现可能是采样异常，也可能只是噪声变大——属于最难查的一类问题。反过来，它也是最好的写路径验证： 写成功后读回 0x83 而不是 0xAA，就证明写真的生效了。
默认值已经正确的：0x26=0x0A、0x27=0x05、0x28=0x04、 0x2F=0x14、0x34=0x03、0x35=0x27。写与不写等价，第一轮可以省下 6 次写事务。

三、我们要写的 9 项（这就是最终清单）

顺序不是随手排的：0x33 必须最后写，它一开，芯片就按前面的参数开始连续转换。
/* 校准通过后按此顺序写入，两颗芯片同值 */
0x0C = 0x83;   /* Test_Reg0 固定值（默认 0xAA 是错的） */
0x09 = 0x20;   /* bit5=1：0x0B 的 0x8 表示 24x；低 4 位 0：LED 电流 0 */
0x0B = 0x88;   /* LNA 24x + PGA 22.8x */
0x29 = 0x60;   /* 24x 的 LNA trim，必须随 0x0B 一起改 */
0x2A = 0x28;   /* 24x 的 LNA trim，必须随 0x0B 一起改 */
0x0F = 0x1F;   /* 采样间隔低 8 位：31 */
0x10 = 0x20;   /* 高 4 位=0，[7:4] 固定 2 → 31*4 = 124us */
0x32 = 0x01;   /* 按下数值变小；SPS 关闭；[3:0] 固定 1 */
0x33 = 0x80;   /* 最后写：连续转换开，硬件 baseline 关 */
1
0x0C = 0x83
先把“出厂设置”改对。默认 0xAA 是错的，后面所有写入都建立在这个基础上。
2
0x09 = 0x20
这是 LNA 档位的“第二选择位”，同时管 LED 总电流。bit5=1 时 0x0B 的 0x8 才是 24×； bit5=0 会变成 16×。低 4 位给 0，LED 电流为 0（Lina 的霍尔 LED 引脚未接）。
3
0x0B = 0x88 → 0x29 = 0x60 → 0x2A = 0x28
放大倍数由三个寄存器共同决定，必须连续写完。只改 0x0B 不改 trim， 等于换了档却没校准前端，线性度会变差。
4
0x0F = 0x1F → 0x10 = 0x20
采样间隔拆成低 8 位与高 4 位，先低后高。31×4 = 124 µs，与 H5 对齐。
5
0x32 = 0x01
告诉芯片“按下时 ADC 值变小”，并保持 SPS 关闭。默认 0x41 是“变大 + SPS 开”，两处都不对。
6
0x33 = 0x80（最后）
总开关。默认 0x00 是单次转换，所以现在读不到连续数据；写 0x80 后芯片开始连续转换。 一旦开启，后面的写入就发生在“转换进行中”，所以必须放在最后。

五、H5 → H6：搬功能，不搬地址

H5 的 25 项配置里真正生效的只有五类；两代芯片地址含义几乎完全不同，按地址照抄必错。

六、四个决策：推荐 + 什么实测会让我改主意

① 硬件 baseline 开不开

0x33 bit2：0（关）还是 1（开）
推荐：先关（0x33 = 0x80）
  • H5 没有硬件 baseline，Lina 的基线、Rapid Trigger 全在 my_misc.c 里；
  • 开启后芯片会调整返回的 14 位值，语义改变，上层要重新验证；
  • 关闭时就是“纯原始值”，与 H5 完全一致，改动最小。
会让我改主意：关闭后观察到松开位置的原始值随温度明显漂移、软件基线跟不上； 那时再打开做 A/B，并重测 Rapid Trigger 的阈值。

② 采样间隔

XENO 28 µs（0x0F=0x07）还是 H5 的 124 µs（0x1F）
推荐：124 µs，对齐 H5
  • MCU 每 1 ms 读一次，124 µs（8 kHz）已足够；
  • XENO 用 28 µs 是为键盘 32 kHz 上报，我们用不上；
  • 间隔越短功耗越高。
会让我改主意：如果实测发现 1 kHz 读取时相邻样本差异异常大（说明转换没跟上）， 再降到 62 µs 或 28 µs 对比。

③ 增益起点

0x88（24×/22.8×）还是 0x99（48×/24×）
推荐：0x88 起步，按实测调
  • 0x88 是 XENO 的默认组合，手册配对明确（0x60/0x28）；
  • 0x99 的总增益 48×24 = 1152，数值上恰好等于 H5 的 64×18，作为“幅度不够”的备选；
  • 判断标准看按下与松开之间的差值，不看绝对值。
会让我改主意：差值小于约 3000 判为不够、升 48×；接近 16383 或出现 0x3FFF 判为饱和、降 16×。

④ 8 个未公开寄存器

0x13/0x15/0x16/0x18/0x1C/0x1E/0x20/0x25
推荐：第一轮不写，出问题再整组加
  • 手册没有定义，但 XENO 在真实产品里写它们，很可能是模拟前端 trim；
  • 先证明“手册公开的最小配置”能工作，变量最少；
  • 若噪声大、零点偏、左右不对称，再整组加进去做 A/B，一次只改一组。
会让我改主意：关闭状态下噪声或零点明显差于预期，且排除了磁铁、机械、供电因素。

读回之后立刻做一次连续采样：数值应随按压单调变化、CRC 一直通过。若完全不变化，先怀疑磁铁位置与 0x32 的极性， 而不是增益——增益错只会让变化幅度变小，不会让变化消失。

八、常见错误（这五个最常踩）

错误现象正确做法
漏写 0x0C（留在 0xAA）采样噪声大或数值异常，难定位第一笔就写 0x83
选 24× 却没设 0x09 bit5增益怎么调都偏小（实际 16×）0x09 = 0x20
只改 0x0B，不改 0x29/0x2A线性度变差、两端压缩三者连续写
提前写 0x33后续配置在转换进行中写入0x33 最后
把 H5 的值抄到 H6 同名地址例如抄 0x13/0x16/0x18，含义完全不同只按功能映射

九、自测五问

1. 哪个寄存器的默认值是错的？

0x0C：默认 0xAA，要求写 0x83。

2. 想把 24× 换成 48×，要改哪几个寄存器？

0x0B = 0x99（LNA 0x9=48×，PGA 0x9=24×）、0x29 = 0xA0、 0x2A = 0x40；0x09 的 bit5 保持 1。

3. 为什么 0x33 必须最后写？

它一开连续转换，芯片就按当前参数开始跑；之前没写完的寄存器会在转换进行中被改。

4. H5 的 0x0A=0x0B 能直接抄到 H6 的 0x0F 吗？

不能。H5 是 值×4+80，H6 是 值×4；抄过去会得到 44 µs 而不是 124 µs。

5. 写完读回 0x00 或 0xFF，说明什么？

写没生效。先查时钟线/MOSI 帧，再查 CRC（含地址位）与 bit14 位置；不要先怀疑芯片坏。
