# 写路径实测通过（0x07）

数据：`untitled.csv`（46,061 字节，`sha256 bbaa9cf0…`，双通道 SCLK+MISO/MOSI 尝试）+ USB 日志截图。固件为 Codex 的 `Hall_H6_TestReg07()` 版本。只分析，未改代码。

## 1. 日志结果

```
H6_REG35 R=0x27 L=0x27 R2=0x27 L2=0x27 R3=0x27 L3=0x27
H6_WR07 R=0x11 L=0x2A
H6_WR07_RST R=0x00 L=0x00
H6_CAL PASS n=16 w0=0x0082 w1=0x0083
```

- 写入前半 0x11、后半 0x2A → 回读**完全一致**；
- 恢复写 0x00/0x00 → 回读 0x00/0x00；
- 0x35 读回与上一轮相同，未受影响。

## 2. 这证明了什么

1. **含地址位的 `CRC_WR` 正确。** 0x07 的 6 位地址是 `000111`（3 个 1，奇校验）。若沿用 H5 的“只算数据位”规则，CRC 会差 1 位、帧被芯片丢弃，回读就会是 0x00。实测读回 0x11/0x2A，说明地址位确实参与了校验。
2. **写帧格式正确**：bit15=1、bit14=CRC、bits13:8 地址、低字节数据。
3. **半区映射自洽**：前半写入 0x11、前半读回 0x11；结合链路末级是 H2，前半即 H2/右键。
4. **写可被覆盖**：第二轮恢复为 0x00 并读回确认。

## 4. MOSI 通道是空的

CSV 里 Channel 15 的 1,841 行**全部为 0、只有 1 次跳变**，即整段采集 MOSI 从未变高。结合写操作确实成功（回读证明），判断是**探头没接到 MOSI_0 或接触不良**，不是固件问题。

要解帧的话需要重新接：Lina 上 MOSI_0 = MCU PIO0_21，也就是 H1 的 SDI（第 2 脚）；`CH15 → H1 pin2`，地线共用。SPI 解码设置：Clock=CH1、MOSI=CH15、8 位、MSB first、空闲低、下降沿采样（CP0/CPHA1）。

不过写路径已经由回读证明，MOSI 解码属于“锦上添花”，不影响进入下一步。

## 5. 下一步

写路径已具备实测依据，可以开始**写 H6 配置表**。建议顺序：

1. 固定/测试寄存器：`0x0C=0x83`（默认 0xAA，写后读回可当第二次写验证）、`0x26/0x27/0x28=0x0A/0x05/0x04`、`0x34=0x03`、`0x2F=0x14`；
2. 采样间隔：`0x0F=0x1F`、`0x10=0x20`（124 µs，对齐 H5）；
3. 增益：`0x0B` 与 `0x29/0x2A` 联动，先从默认 `0x15` 起步，等采样看原始值幅度再定；
4. 极性/按键类型：`0x32`，先写 `0x01`（按下值下降、关 SPS），方向不对再改 bit6/bit7；
5. baseline：`0x2D/0x2E` 初值、`0x30/0x31=0x20/0x20`；
6. **最后**写 `0x33=0x84` 打开连续转换 + baseline；
7. 读回 `0x0C/0x0F/0x10/0x32/0x33` 逐项比对，作为配置生效的证据。
