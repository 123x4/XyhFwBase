# Lina H6 迁移协同开发交接

## 项目与工作区

- 项目为 `XyhFwBase/EM_HapticMouse` 的 GT Lina T1A Hall Haptic 鼠标固件，MCU 为 LPC11U37/501。本次从 H5（GTRY154）迁移到 H6（GTRY164），需要兼容 H5 和其他既有板型。开发习惯是阶段性验证、最小改动、复用现有入口，每次答复保存在 `Codex_Analysis/`。芯片手册、原理图、XENO H6 参考工程和 MG380U Bootloader 在 `Materials/`。
- 同一个 `Sample.uvproj`、`Target 1`，在 `inc/my_board.h` 的版型列表选 `GT_LINA_T1A_H6_PWM` 或 `GT_LINA_T1A_H5_PWM`。当前选 H6。H6 内部复用旧 H5 板级别名来沿用 Lina GPIO、SSP1 和触觉 PWM。H6 协议区分用 `GT_LINA_T1A_H6_PWM`。 [版型配置](../inc/my_board.h#L25)
- 固件在远程 Linux 工作区开发。Windows 台架有 Keil ARMCC 5.06 update 7 build 960 和 Saleae。远端可做 Clang 编译、预处理和模拟检查。Windows 可解压本项目测试包，重建 `Target 1`，烧录本次生成的 `output/Sample.hex`。应用链接地址是 0x4000。用调试器烧录时按应用扇区处理，以保留 Bootloader。 [工程](../Sample.uvproj) · [测试包](Lina-H6-校频诊断-Windows.zip)
- 当前本地 `main` 的 HEAD 为 `3f3622d`，领先 `origin/main` 12 个提交。读 `0x35` 的代码、同步后的 Windows ZIP 和诊断说明在工作区尚未提交。协作者应以本地工作区为准，从远端只拉代码会少这批改动。动手前先看 `git status` 和 `git diff`，再明确各自负责的文件或函数。

## 硬件和当前诊断流程

- 两颗 H6 共用 `SCLK_0`。MCU 的 `MOSI_0` 先进 H1 左键，经 `SDO_0` 串到 H2 右键，最后通过 `MISO_0` 回 MCU。SCK 接 PIO1_15，SSP1 用于双芯片数据移位，每段 32 个短时钟，字节内实测 2 MHz。Saleae 可先用 CH1 单独抓 SCK，另加 CH15 时再看数据线。
- 入口是 `HallSensor_INIT()`。选 H6 时运行 `Hall_H6_Diagnostic()`，冷启动校频至少 16 次，上限 128 次。成功后等 20 ms，再做寄存器诊断。之后保存在内存的结果通过 USB 每秒输出一次。该版本主要用于校频和寄存器验证，正常 Hall 采样、Rapid Trigger 和触觉联调尚未迁移。 [诊断入口](../app/button.c#L988)
- USB 应用 VID/PID 为 `1A81:2071`，日志走厂商 HID 接口。Windows 可运行 `py .\tools\h6_usb_log.py --once`，首次可用 `py -m pip install hidapi` 安装依赖。诊断循环调用 `PC_Communicate()` 处理应用态入 Boot 请求，Bootloader 的 VID/PID 是 `17EF:6155`。 [日志工具](../tools/h6_usb_log.py) · [升级命令](../src/pc_communicate.c#L882)

## 已通过的 td10

- 共用入口 `Hall_CLK_Command_SET()` 内使用现有 `CT16B1_DelayUs()`。H6 在高电平定时器延时后执行 31 条字面 NOP，并用 PRIMASK 防止高电平被中断拉长。校频调用定版为 `Hall_CLK_Command_SET(126U, 60U)`，31 拍尾部、临界区和 td10 参数已定版。5 µs 的 td1 和 39 µs 的 td6 分别验收。 [计时代码](../app/button.c#L807)
- 31 拍版 16 条的高脉宽均值 **127.9992 µs**，极差 **0.0125 µs**，低等待 **62.81–67.50 µs**，每条 32 个时钟。日志为 `H6_CAL PASS n=16 w0=0x0084 w1=0x0083`，两个低字节都在 `0x7C–0x84`。CSV 的 SHA-256 以 `b953b9e9` 开头。 [定版记录](2026-11-25-H6校频尾部31拍.md) · [原始 CSV](untitled.csv)

## 当前待验收的 0x35 读回

1. 已实现校频通过后读三次 `0x35`。每次 SSP1 先发送 `35 00 35 00`，再使用 `Hall_CLK_Command_SET(37U, 4U)` 发 td6、等待 td5，随后再移位 4 字节并保存回复的第 2、4 字节。读标志为 0，寄存器读回按低字节判断。三次结果先打印为一行 `H6_REG35`，再打印 `H6_CAL`，方便现有 `--once` 命令一次取全。 [代码](../app/button.c#L1017)
2. ARMCC 构建、板上寄存器回读和 td6 波形待验收。用新版包在 Windows 重建烧录，Saleae CH1 接 `SCLK_0`，80 MS/s、1–2 s、高脉宽触发 **20–60 µs**，先 Start 再上电。用新文件名导出 CSV。需要核对三条 td6 **37.05–40.95 µs**、下降沿到第一枚回读短时钟 **大于 3 µs**，前后各 32 个短时钟，以及 `H6_REG35` 六个值均为手册默认 **0x27**。同时收 `H6_CAL`。若出现 `0x00` 或 `0xFF`，先留存原始日志，再追加 MOSI/MISO 波形。 [完整复测步骤](2026-11-25-H6寄存器35读回诊断.md)
3. 日志里的 R/L 暂沿用旧 H5 字序，同值回读只验证寄存器事务。0x35 通过后，再设计 `0x05` 的互异值读写与恢复原值测试来确认链序。此后实测 td1 的 **4.75–5.25 µs** 窗口并验证 H6 采样帧的两位奇偶校验，最后才接回基线、Rapid Trigger 和触觉。
4. 以 GTRY164 V1.9 的图和时序表为准，交叉核对 XENO。H6 的 `td4` 是 PWM，寄存器读写使用 `td6`。寄存器写帧和 14 位采样帧的校验分别按手册处理。XENO 用到 `0x36/0x37/0x3B` 做偏差校准，手册未公开这些地址。还要留意 16× LNA 下 `0x29/0x2A` 的手册值和 XENO 值不同，等基础通信通过后再核对芯片版本及实测表现。 [手册与 XENO 差异](2026-11-24-H5迁移H6-阶段1.md)
