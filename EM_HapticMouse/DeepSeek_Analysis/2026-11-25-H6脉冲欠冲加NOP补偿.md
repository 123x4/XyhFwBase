# H6 脉冲：定时器欠冲 + NOP 补偿（取代 MR0 方案）

补丁：[H6-pulse-compensation.patch](H6-pulse-compensation.patch)，针对当前已提交的 `app/button.c`（`0fbede9`，TC 轮询版）。本轮只出补丁，未改工作区源码。

## 1. 为什么换这个方案

三个数放在一起看：

| 现象 | 数值 |
| --- | --- |
| trim=0 实测 | 128.6862 µs |
| trim=−33 实测 | 127.7913 µs |
| 两次差 | 0.895 µs 对应 33 拍，即退出量化约 0.2 µs |

轮询 `TC` 的“检测延迟”是量化误差的来源：定时器到期时刻再准，也要等下一次读到才退出。MR0 方案只是把到期判断交给硬件，**检测仍然靠轮询**，量化不会消失，只是循环变短、格点变细；还要额外处理 `TIMER_16_1_IRQn` 在 NVIC 里的使能状态（`gtech_flash` 会打开它）。

既然量化无法消除，就**故意欠冲**：让定时器停在目标之下（超出量化上限），再用**精确的 NOP 序列**补回最后一段。NOP 的每一步是 1 个 48 MHz 周期（20.83 ns），与轮询相位无关，所以补偿不会引起跳格；量化被“欠冲”吸收，精度由 NOP 决定。

## 2. 补丁内容

```c
#define H6_PULSE_TRIM_COUNTS    (-41)   /* 0.854 us below nominal */

#define H6_COMP_1()    __NOP()
#define H6_COMP_2()    H6_COMP_1(); H6_COMP_1()
#define H6_COMP_4()    H6_COMP_2(); H6_COMP_2()
#define H6_COMP_8()    H6_COMP_4(); H6_COMP_4()
#define H6_COMP_16()   H6_COMP_8(); H6_COMP_8()
#define H6_COMP()      H6_COMP_16(); H6_COMP_2()   /* 18 NOPs = 375 ns */
```

调用点只在轮询退出之后、拉低 SCK 之前：

```c
    while ((uint16_t)(LPC_CT16B1->TC - start) < counts)
    {
    }
    H6_COMP();
    LPC_GPIO->CLR[1] = sckMask;
```

数值关系（以当前 −33 版实测的固定开销 0.479 µs 为基准）：

```
定时器到期 = 128 − 41/48 = 127.146 µs
+ 轮询检测 ≈ 0.479 µs      → 127.625
+ 18 NOP    = 0.375 µs      → 128.000
```

NOP 保持在 PRIMASK 临界区内，仍是高电平的一部分。

## 3. 标定方法

1. 先按补丁的 `H6_COMP() = 16 + 2 = 18` 重建、抓 16 条。
2. `delta = 128.00 − 实测均值`，需要增减的 NOP 数 = `round(delta / 0.020833)`。
3. 在 `H6_COMP()` 这一行加/减整拍（例如要 24 拍就写 `H6_COMP_16(); H6_COMP_8()`），重建复测。

可调范围 0–24 拍（0–500 ns），覆盖量化上限。分辨率 20.83 ns，80 MS/s 采集的 12.5 ns 量化已经比它细，够用。

## 4. 一个需要留意的编译风险

`__NOP()` 无副作用，理论上编译器可以在不改变语义的前提下挪动它们。若复测发现“增删 NOP 后脉宽不变”，说明被挪到了 `CLR` 之后，请告诉我，改用 `volatile` 读或内联汇编做屏障。正常情况下 ARMCC 5 会按书写顺序保留 `__nop`。

## 6. 这个方案对 td6 / td1 的意义

补偿是**绝对量**（0.854 µs 欠冲 + 0.375 µs 补回），与脉宽无关，所以：

| 用途 | 欠冲后到期 | + 开销 + NOP | 预期 |
| --- | ---: | ---: | ---: |
| td10 128 µs | 127.146 | +0.479 +0.375 | 128.000 |
| td6 39 µs | 38.146 | +0.479 +0.375 | 39.000 |
| td1 5 µs | 4.146 | +0.479 +0.375 | 5.000 |

这正是之前 trim 单点标定做不到的：td1 的 ±0.25 µs 窗口以前被 0.2 µs 的量化吃掉大半，现在由 NOP 把最后一段补准。仍建议 td1 单独抓一次确认。

- 应用后 `H6_PULSE_TRIM_COUNTS` 的含义要从“整段标定”改成“欠冲量”，注释已写明。
