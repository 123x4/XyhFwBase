# H6 诊断版入 Boot 修复

截图显示升级器停在 `Enter bootloader...`，同时显示 `17EF:6155`。参考 MG380U Bootloader 的 USB 描述符使用这个 ID，Lina 应用态使用 `1A81:2071`。以 Windows 此刻实际枚举的 ID 为准，可以在 PowerShell 运行：

```powershell
Get-PnpDevice -PresentOnly | Where-Object {
    $_.InstanceId -match 'VID_(17EF&PID_6155|1A81&PID_2071)'
} | Select-Object Status, FriendlyName, InstanceId
```

- 若当前有 `17EF:6155`，板子已经在 Bootloader。保持板子连接，关掉日志窗口和升级器，再重新打开升级器尝试连接 Bootloader。如仍卡住，记录 Windows 枚举结果和升级器状态，继续查 Bootloader 枚举后的连接或握手。
- 若当前只有 `1A81:2071`，且板子运行的是修复前的 H6 诊断版，旧程序在霍尔初始化中循环输出日志，遗漏了 `PC_Communicate()`。这时旧程序不会响应升级器的应用态入 Boot 命令。可用已有 J-Link/SWD 路径写入修正版应用区 `0x4000`，选择按使用扇区擦除，以保留 Bootloader。

固件已把现有的 USB 入 Boot 命令接入 H6 诊断循环。H6 分支识别原有的两个 `0x11` 命令格式，第二种保留 CRC 检查，随后调用原有 `Bootloadable_Load()` 写入 SRAM 标记并软复位。新版仍通过原工程重建。已验证三种既有版型的预处理结果，并用模拟 USB 包验证接受及拒绝路径。Windows 实际构建、板上切换和升级工具握手仍待验证。
