# H6 计数版首测与 −33 拍校准

新版计数式脉冲在 `trim=0` 下的 [CSV](untitled.csv) 含 1057 条状态记录、16 条完整校频事务。高脉宽取长脉冲上升沿至下降沿，低等待量到首枚短时钟上升沿。

| 项目 | 实测 |
| --- | --- |
| 第一条高脉宽 | 128.68 µs |
| 高脉宽均值 | 128.68625 µs |
| 高脉宽范围与极差 | 128.68–128.69 µs，极差 0.01 µs |
| 低等待 | 62.08–66.86 µs，全部大于 50 µs |
| 后续短时钟 | 每条 32 个，字节内周期约 0.50 µs |

从最后一枚短时钟下降沿到下一条长高脉冲，第 1、2 条之后分别是 6.02 和 6.12 µs，第 3–15 条之后约 20.095 ms。按当前代码，20 ms 等待只在双芯片回读通过后执行，因此波形支持前两次回读未通过、第 3–15 条通过的推断。第 16 条仍需本次原始 `H6_CAL` 日志确认。

实测均值比 128.00 µs 长 0.68625 µs。以 48 MHz 换算，`round((128.00 - 128.68625) × 48) = -33`。已将 `H6_PULSE_TRIM_COUNTS` 从 0 改为 −33，校频目标计数从 6144 调到 6111。线性估算的均值约为 127.99875 µs，实际轮询退出和 GPIO 边沿需上板复测。该补偿目前只依据 td10，5 µs 的 td1 和 39 µs 的 td6 仍需分别验收。 [补偿位置](../app/button.c#L813)

H6 脉冲分支通过 Cortex-M0 Clang 的转换及符号比较警告检查。新版源码已打包，ARMCC 重建与实体板复测仍待完成。复测沿用原 Saleae 设置，导出 16 条 CSV 和一行 `H6_CAL`，核对高脉宽均值 128.00 ±0.10 µs、极差 ≤0.20 µs、低等待 >50 µs 和每条 32 个短时钟。 [Windows 测试包](Lina-H6-校频诊断-Windows.zip)
