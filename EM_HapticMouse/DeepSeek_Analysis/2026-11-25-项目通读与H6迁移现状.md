# 项目通读与 H6 迁移现状（DeepSeek 接入第一次阅读）

本轮只阅读，未改动任何代码。核对方式：逐个阅读 `app/`、`src/`、`inc/` 的相关模块，用 `pdftotext` 抽取 `Materials/` 下三份 PDF 的文字，并把 Lina 原理图渲染成图逐区看图核对网络名；再用 `git status/diff` 区分已提交与工作区未提交的改动。

## 1. 项目是什么

Lina T1A（GT_Lina G2 V0.1）双霍尔磁轴鼠标：LPC11U35FHI33 + PAW3950 光学传感器 + 两颗 GTRY154/GTRY164 霍尔（左键 H1、右键 H2）+ 双线圈触觉（LRA 驱动方案，HP_EN/PWM1/PWM2）+ USB HID 与厂商命令通道。

- 固件入口：`main()` → `Device_Init()` → `Device_Active()` 死循环。 [Main.c](../src/Main.c#L13)
- 初始化顺序：看门狗 → 系统 48 MHz 时钟 → GPIO → `Ele_Init()`（触觉）→ 可选 UART → USB 时钟 → `Param_Init` → `MyDebug_Init` → Lina 走 `InitSPI1Master()` → CT16B0 1 ms 中断 → USB 初始化 → 500 ms 延时 → `HallSensor_INIT()` → 恢复出厂/Flash/Profile → PAW3950 → `Custom_Init` 等。 [device.c](../src/device.c#L273)
- 主循环：`Device_Scan()` → `Device_Pack()` → `Device_Report()` → `wwdt_feed()` → `PC_Communicate()` → `Suspend_Check()` → `Ele_PollingTask()` → `Task_ParamGuard()` → `MyDebug_Task()`。 [device.c](../src/device.c#L347)
- 1 kHz 节拍来自 CT16B0 中断递减 `one_ms_cycle`，`Device_Scan()` 在 `one_ms_cycle==0` 时执行一次按键/霍尔任务。 [Timer.c](../src/Timer.c#L78) · [device.c](../src/device.c#L729)

## 2. 霍尔 H5 数据链（当前固件真实路径）

`Device_Button_Scan()` → `Button_Scan()` → `Button_GetState()` → `LR_GetState()` → `hall_get_sample()`（一次 GPIO 命令脉冲 + 一次 4 字节 SSP1 收发）→ `ProcessRecvSampleRawData()`。 [button.c](../app/button.c#L317) · [button.c](../app/button.c#L869) · [my_misc.c](../src/my_misc.c#L418)

注意：`src/my_hallkey_func.c` 里有同名函数，但该文件**不在** `Sample.uvproj` 的源文件列表里，实际参与编译的是 `src/my_misc.c` 的版本。以后若把前者加进工程会直接重复定义。 [Sample.uvproj](../Sample.uvproj)

`ProcessRecvSampleRawData()` 的关键处理：

1. 用 `ana_phy_bit_error_checker2()` 检查高字节 bit7/bit6 两个偶奇校验，失败返回 `CRC_ERROR`。 [my_misc.c](../src/my_misc.c#L398)
2. Lina PWM 版型 `PRESS_KEY_AND_VALUE_INCREASE=0`，所以做 `16383 - raw` 反转，使“按下”对应值变大。 [my_misc.h](../inc/my_misc.h#L39) · [my_misc.c](../src/my_misc.c#L531)
3. 一阶滑动滤波（`FILTER_SKIP_VALUE=60`）→ `Hall_CalculateNode()`（top/bottom baseline 归一化到 0–100 分段）→ `Hall_HandleKeyRapidTrigger()`（AP + RT 按下/抬起行程）→ `Ele_UpadteSegment()` 送触觉模块。 [my_misc.c](../src/my_misc.c#L547)
4. `gbKeyState[]` 再回到 `Button_Scan()` 的边沿检测，触发 `Ele_LeftKeyPressProcess()` / `Ele_LeftKeyReleaseProcess()`（阻塞式线圈脉冲）并写进 `scan_result_pre`。 [app/button.c](../app/button.c#L611) · [my_electromagnet.c](../src/my_electromagnet.c#L1005)

采样数组约定（H5 已验证）：`rx[0..1]` = 右键 H2 帧，`rx[2..3]` = 左键 H1 帧，低 8 位有效；14 位数据 = `((hi & 0x3F) << 8) | lo`。

## 3. 硬件接线（按原理图核对）

| 信号 | MCU | 网络/去向 |
| --- | --- | --- |
| Hall SCK | PIO1_15（SCK1） | `SCLK_0`，H1/H2 第 3 脚共用 |
| Hall MOSI | PIO0_21（MOSI1） | `MOSI_0` → H1 SDI |
| Hall MISO | PIO0_22（MISO1） | H2 SDO → `MISO_0` |
| 级间 | — | H1 SDO → `SDO_0` → H2 SDI（MCU→H1→H2→MCU） |
| 霍尔供电使能 | PIO0_16 | `Hall PWR EN`/TP11，高电平经 Q5 拉低 MOS1 栅极 → `HALL_VDD`（TP8）≈3.3 V |
| 触觉 | PIO1_19 / PIO0_13 / PIO0_14 | `HP_EN` / `PWM1` / `PWM2` |

原理图里 H1 标注 `LB`、H2 标注 `RB`；GPIO 初始化先拉低、等 50 ms、再拉高使能霍尔电源。 [GPIO.c](../src/GPIO.c#L575) · [my_board.h](../inc/my_board.h#L345)

## 4. H5 与 H6 的实测/手册差异（已逐条对照手册）

指令编号与时序（H6 §7.8 第 12 页）：

| 操作 | H5 | H6 |
| --- | --- | --- |
| Hall 转换 | td1 5±5%，td2 连续 >2 / 单次 >80 | td1 5±5%，td2 连续 >4 / 单次 >24 |
| 写/读寄存器 | td4 24±5%，td5 >2 | td6 39±5%，td5 >3 |
| PWM 写入 | td3 9±5% | td4 18±5%（正文误写 td3） |
| 频率校准 | td7 128±5%，td10 >2 | td10 128±5%，td12 >50 |
| 睡眠/唤醒 | td11 15±5%，td12 >2，td13 >12 | td7 28±5%（睡眠），td8 2±5% + td9 >50（唤醒，正文误写 td12/td13） |
| 软复位 | 无 | td11 >1280，td9 >50 |

其他关键差异：

- **寄存器表整体不同**。H5 的 `0x0A/0x0D/0x12/0x13/0x14/0x16/0x17/0x18/0x19–0x21/0x27` 在 H6 里要么换了含义、要么未定义；H6 新增 `0x0B Gain_Config0`、`0x0F/0x10` 采样间隔、`0x1B` SCK 空闲、`0x29/0x2A` LNA 联动 trim、`0x2B/0x2C` 按键阈值、`0x2D/0x2E/0x30/0x31` TOP baseline、`0x32` 按键类型/极性、`0x33` 工作模式、`0x35` SDO 驱动、`0x3C` 实时 baseline。 [H6 §8 第 13–17 页](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=13)
- **写寄存器 CRC 含地址**：H6 的 `CRC_WR = A5^…^A0^D7^…^D0`，H5 只异或数据位。现有 `bit_crc_write_reg[256]` 只算数据位，直接沿用会被芯片判为无效帧。 [H6 §7.4 第 10 页](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=10) · [button.c](../app/button.c#L30) · [XENO 写帧](../Materials/GT_SS_XENO_APP_20260916/src/h6/h6_drv.c#L74)
- **读寄存器事务结构不变**：移位帧 → 长命令脉冲 → 低等待 → 再移位读回；H6 只是把 td4/td5 换成 td6/td5。
- **采样数据格式不变**：16 位，高 2 位 CRC1/CRC0，低 14 位数据，CRC 定义与 H5 一致，所以现有 `bit_error[]` 校验和 `0xC000/0x3FFF` 异常值识别可继续用（这两个值都会被判成 CRC 错）。
- **采样间隔语义不同**：H6 `Sample_Interval = 0x0F + (0x10[3:0]<<8)`，单位 4 µs，不可配 0x0–0x6；`0x10[7:4]` 必须写 0x2。
- **极性**：H6 `0x32` bit6=1 表示“按下 ADC 值变大”，bit7 是磁场极性反转；Lina H5 的既有约定是“按下原始值变小 + 固件取反”，对应 H6 写 bit6=0（默认 `0x41`/XENO 用 `0x01` 就属于这一类），但必须上板确认原始值方向。
- **H6 手册未公开但 XENO 在用的寄存器**：`0x13/0x15/0x16/0x18/0x1C/0x1E/0x20/0x25`，以及偏移校准用的 `0x36/0x37/0x3B`。`0x29` 在 16× 时 XENO 写 `0x4E`，手册写 `0x50`。 [h6_hal.c](../Materials/GT_SS_XENO_APP_20260916/src/h6/h6_hal.c#L1196) · [h6_offset_cali.c](../Materials/GT_SS_XENO_APP_20260916/src/h6/h6_offset_cali.c#L418)

## 5. 当前 H6 工作区状态（已与代码逐条核对）

- 板型：`my_board.h` 只启用 `GT_LINA_T1A_H6_PWM`，它在内部再定义 `GT_LINA_T1A_H5_PWM`→`GT_LINA_T1A_H5`，从而复用 Lina 的引脚、SSP1、霍尔供电和触觉宏。 [my_board.h](../inc/my_board.h#L27)
- 诊断入口：`HallSensor_INIT()` 在 H6 版型下直接进 `Hall_H6_Diagnostic()`，**不返回**；它循环 16–128 次校频，判据 `rx[1]`、`rx[3]` 都落在 `0x7C–0x84`，通过后等 20 ms，最后停在 USB 日志循环里每秒打印一次 `H6_CAL` 并处理入 Boot 命令。 [button.c](../app/button.c#L965) · [button.c](../app/button.c#L1015)
- 命令脉冲：没有单独的 H6 实现，直接复用 `Hall_CLK_Command_SET()` 的 Lina 分支（PIO1_15 切 GPIO → 拉高 → `CT16B1_DelayUs(high)` → 拉低 → `CT16B1_DelayUs(low)` → 切回 SCK1），H6 只多了一个可选的一拍 `__NOP()`。 [button.c](../app/button.c#L807)
- 实测（11-25）：高脉冲 127.875 µs、低等待 61.4 µs、32 个短时钟、时钟 2 MHz；USB 日志 `H6_CAL PASS n=2 w0=0x0083 w1=0x0084`。注意这组 127.875 µs 属于**更早的 6144 计数版实现**，当前实现改成 `CT16B1_DelayUs()` 后（10:2x 起调用 `DELAY_OUT(128)=127`）尚未重新测量。
- 诊断期间 `Device_Init()` 后面的步骤全部没执行（PAW3950、Flash/Profile、`Custom_Init`、`RamMalloc_Init`、LED、BOD），`PC_Communicate()` 也被替换成只处理升级命令的简化版。 [pc_communicate.c](../src/pc_communicate.c#L882)

## 6. 我核对出的问题与风险

1. **文档与代码已有漂移。** 11-25 笔记里的 `Hall_H6_SendCommand(highTicks, lowTicks)`、6144/6150 拍、中断状态保存恢复，在当前工作区都已不存在；现在传入的是微秒值 `Hall_CLK_Command_SET(128U, 60U)`，且只关/开 `USB_IRQn`，不是保存恢复 PRIMASK。引用旧笔记时要以代码为准。
2. **一拍 NOP 补不了 0.125 µs。** 实测差 6 个 48 MHz 周期（125 ns），`H6_SCK_HIGH_TRIM_ONE_CYCLE` 只加 1 拍（20.8 ns）。当前值本来就在规格内（误差 0.098%），要精确 128.000 µs 得补 6 拍或改定时器基准，不然这个宏只会带来新的误解。
3. **`DELAY_OUT()` 与直接传微秒混用。** `DELAY_OUT(x)=x-1` 是给旧 `DrvGPIOOutput` 补偿用的；H6 诊断现在传原始 128/60，实测≈127.9/61.4。后续 H6 正常采样若继续用 `TD1/TD2/TD4/TD5` 这些 H5 宏，会用到 24 µs 命令脉冲和 5 µs 低等待，不满足 H6 的 td6/td12，必须单独一套 H6 时序，而不是把 `USE_HALL_SENSOR` 改成 6。
4. **H5 的 td1 实测 5.2875–5.30 µs 已超 H6 td1 上限 5.25 µs**（现有参数是 `DELAY_OUT(5)=4`）。H6 采样脉冲需要重新标定，不能照搬。
5. **H6 初始化寄存器表需要重写**，且 XENO 依赖 8 个手册未公开寄存器；`0x29` 的 16× 值手册与 XENO 不一致。首版建议只用“手册公开 + XENO 固定值”的最小集，并逐项记录依据。
6. **写寄存器 CRC 会静默失败**：不改 CRC 算法，写命令不会报错但寄存器不生效，容易误判成“芯片不响应”。
7. **ROM/RAM 余量小。** 历史 MAP：ROM 44.64 KiB / 48 KiB（约 3.3 KiB 余量），RW+ZI 7032 / 7776 B（约 744 B 余量），加 H6 表和新代码要留意。 [Sample.map](../List/Sample.map#L1785)
8. **链序/左右映射还没在实物上确认。** 校频只判断低字节范围，两芯片同值，无法区分 H1/H2；`rx[0..1]=右` 目前只有移位分析支撑。建议用 `0x05` 写互异值再读回确认（写帧按芯片分成前后 16 位）。
9. **H6 诊断固件无法从应用态被 GUI 正常识别**：初始化未跑完、`PC_Communicate` 被简化，这是有意为之，但验收时要清楚“这版只是台架诊断固件”。
10. **`my_hallkey_func.c` 未编译**，它的 `void ProcessRecvSampleRawData()` 与 `my_misc.c` 的 `uint8_t` 版本签名不同；不要为省事直接把它加进工程。

## 7. 建议的下一步（阶段 2）

1. 先做**寄存器读事务**：读 `0x35`（默认 `0x27`），td6≈39 µs、td5≥4 µs，验证读回 16 位且低 8 位为 `0x27`；同时抓 SCLK + MOSI + MISO 确认字节对齐。 [H6 图 7 第 10 页](../Materials/GTRY164%20Magnetic%20Keyboard%20Sensor%20and%20LED%20Driver_V1.9_20261008%20%28Gtech%29.pdf#page=10)
2. 再做**写→读→恢复**：对 `0x05` 分别写互异值确认链序与 H6 含地址 CRC 的写帧；再写 `0x35` 改 SDO 驱动电流并读回，确认写命令真的生效。
3. 然后建 **H6 最小配置表**：`0x0C=0x83`、`0x26/0x27/0x28`、`0x0F/0x10` 采样率、`0x32` 极性/按键类型、`0x2D/0x2E/0x30/0x31` baseline、`0x33=0x84`、`0x35=0x27`；每项标注手册页或 XENO 出处。
4. 最后接**单次/连续转换采样**：先单次（td1 5 µs + td2 >24 µs）看原始值与方向，再切连续（td2 >4 µs）回到 1 kHz 路径，然后逐级接回 baseline/node/RT 和触觉。
