# H6 配置表设计（先讨论，不改代码）

参考源四份：GTRY154（H5）手册、GTRY164（H6）手册、XENO 参考工程、本项目 `app/button.c` 里的 H5 配置表。本文把它们对齐成一张 H6 配置草案，并标出需要实测决定的三项。

## 0. 信息源的取舍原则

| 来源 | 回答什么问题 | 权重 |
| --- | --- | --- |
| XENO 参考工程 | **值该填多少**——唯一一份厂商提供、在真实产品上跑通的 GTRY164 配置 | 值的首要参照；含 8 个手册未公开寄存器与它们的顺序依赖 |
| H6 手册 §8 | 每个地址**是什么含义**、默认值、位定义 | 解释与合法性校验；与 XENO 冲突时先判断是“芯片要求”还是“应用选择” |
| 本项目实测 | 我们这套硬件（磁铁、板子、时序）下的真实表现 | 最终裁决，尤其增益、极性这类与结构相关的项 |
| H5 手册与代码 | “Lina 原来需要什么行为” | 只能做功能映射，绝不能按地址照搬 |

换句话说：**值参考 XENO，含义参考手册，最终以实测为准；H5 只提供需求清单。**

**关键前提**：H5 与 H6 的寄存器地址含义几乎完全不同。H5 的 25 项初始化表（0x0A/0x0C/0x14/0x18…）不能按地址照抄，必须按“功能”重新映射。

## 1. 现有 H5 配置逐项拆解

`app/button.c` 的 `sensor_reg_init_array[25][2]`，按功能归类：

| H5 地址 | 值 | 功能 | Lina 是否真的在用 |
| --- | --- | --- | --- |
| 0x0A | 0x0B | 采样间隔 Fine = 11×4+80 = **124 µs** | 是 |
| 0x0B | 0x00 | 采样间隔 Coarse（SPS 用） | SPS 关闭，实际不生效 |
| 0x0C/0x0D | 0xB5/0x02 | 固定值 | 是（芯片要求） |
| 0x0E | 0x1F | 按键释放超时（SPS 用） | SPS 关闭，不生效 |
| 0x0F/0x10 | 0x00/0x10 | SPS 阈值 | SPS 关闭，不生效 |
| 0x11/0x12 | 0x00/0x47 | 固定值 | 是 |
| 0x13 | 0x01 | 滤波配置（连续模式 fb） | 是（H5 的滤波） |
| 0x14 | 0x35 | LNA 64× | 是 |
| 0x15/0x17 | 0x44/0x7C | 固定值 | 是 |
| 0x16 | 0x04 | PGA 18.0× | 是 |
| 0x18 | 0x8E | LED 使能 + 连续转换 + SPS 关 | 连续转换=是；LED 实际未接 |
| 0x19–0x1C | 0xFF | 4 路 LED 电流 | 未接，无实际作用 |
| 0x1D/0x1E | 0x88/0x88 | LED Imax | 未接 |
| 0x1F | 0x07 | SDO 驱动 12 mA | 是 |
| 0x20/0x21 | 0x00/0x88 | 深度睡眠/固定值 | 是 |
| 0x27 | 0x00 | 温度补偿（关闭） | 关闭 |

结论：H5 真正在工作的只有 **采样间隔、固定值、连续转换、LNA/PGA、SDO 驱动**；SPS、LED、温度补偿在 Lina 上都没有实际作用。

## 2. H5 → H6 功能映射

| 功能 | H5 | H6 | 说明 |
| --- | --- | --- | --- |
| 采样间隔 | 0x0A=0x0B（124 µs） | **0x0F=0x1F、0x10=0x20**（31×4=124 µs） | 数值对齐，间隔语义相同 |
| 连续转换 | 0x18 bit2=1 | **0x33 bit7=1** | H6 拆成了独立寄存器 |
| 固定值 | 0x0C=0xB5、0x0D=0x02、0x11=0x00、0x12=0x47、0x15=0x44、0x17=0x7C、0x20=0x00、0x21=0x88 | **0x0C=0x83**（默认 0xAA）；0x26/0x27/0x28/0x2F/0x34 默认已等于要求值 | H6 固定值少得多 |
| LNA/PGA | 0x14=0x35（64×）、0x16=0x04（18×） | **0x0B**（[7:4]LNA + [3:0]PGA）+ **0x29/0x2A 联动 trim** + **0x09 bit5** | 没有 64× 档，需重选 |
| SDO 驱动 | 0x1F=0x07（12 mA） | 0x35 默认 **0x27**（12 mA） | 默认已一致 |
| 滤波 | 0x13 Filter_Config | 无对应寄存器 | H6 内部处理，无暴露 |
| 温度补偿 | 0x27 | 无对应寄存器 | H6 无此功能 |
| SPS | 0x0E/0x0F/0x10/0x18 bit0 | 0x11/0x12 + **0x32 bit4** | Lina 不用 SPS，保持关闭 |
| LED | 0x18 bit7、0x19–0x1F | 0x05–0x09 | Lina 霍尔 LED 未接，全部保持 0 |

## 3. H6 配置草案（按依赖顺序）

| # | 地址 | 值 | 作用 | 依据 | 状态 |
| ---: | --- | ---: | --- | --- | --- |
| 1 | 0x0C | **0x83** | Test_Reg0 固定值（默认 0xAA，写错会导致行为异常） | H6 p14 | 定 |
| 2 | 0x09 | **0x20** | bit5=1 选 24× LNA；[3:0]=0 → LED Imax=0（不点灯） | H6 p13/p15 | 定 |
| 3 | 0x0B | **0x88** | LNA 0x8（24×，配合 bit5=1）+ PGA 0x8（22.8×） | H6 p13 | 待实测（幅度） |
| 4 | 0x29 | **0x60** | 24× 对应 LNA trim | H6 p15 | 随 0x0B |
| 5 | 0x2A | **0x28** | 24× 对应 LNA trim | H6 p15 | 随 0x0B |
| 6 | 0x0F | **0x1F** | 采样间隔低 8 位 = 31 | H6 p14 | 定 |
| 7 | 0x10 | **0x20** | [7:4] 固定 2，高 4 位 = 0 | H6 p14 | 定 |
| 8 | 0x32 | **0x01** | bit6=0 按下值下降、bit4=0 关 SPS、[3:0] 固定 0x1 | H6 p16 | 待实测（极性） |
| 9 | 0x33 | **0x80** | 连续转换开、硬件 baseline 关、其余位 0 | H6 p17 | 待决策（见 4.1） |

**不需要写**（默认值已等于要求值，写了也是同值）：
`0x26=0x0A`、`0x27=0x05`、`0x28=0x04`、`0x2F=0x14`、`0x34=0x03`、`0x35=0x27`。

**不需要写**（只在 SPS / 中断模式生效，我们不用）：
`0x11`（SPS 间隔）、`0x12`（释放超时）、`0x1B`（SCK 空闲）、`0x2B/0x2C`（按下阈值）。

也就是说：**H6 上电默认已经接近可用，真正要改的只有 9 个寄存器**。

## 4. 四个需要拍板的决策

### 4.1 硬件 baseline 开不开（0x33 bit2）

- H5 没有硬件 baseline，Lina 的基线跟踪、Rapid Trigger 全在固件里（`my_misc.c`）。
- H6 有硬件 TOP baseline（0x2D/0x2E/0x30/0x31/0x33 bit2），开启后芯片会调整返回的采样值。
- **建议先关（0x33=0x80）**：保持与 H5 完全相同的“原始 14 位值”语义，上层 baseline/RT 代码不用改；硬件 baseline 作为以后降功耗或抗温漂的备选，单独 A/B。

### 4.2 增益档

H5 是 64× LNA + 18× PGA；H6 只有 16/24/48/96× LNA 和 13.2–24× PGA。

| 方案 | 0x0B | 0x29/0x2A | 总增益 | 说明 |
| --- | ---: | --- | ---: | --- |
| A（推荐先试） | 0x88 | 0x60/0x28 | 24×22.8=547 | XENO 的默认组合，手册配对明确 |
| B | 0x99 | 0xA0/0x40 | 48×24=1152 | 数值上恰好等于 H5 的 64×18，作为“不够再加”的备选 |
| C | 0x84（bit5=0） | 手册 16× 配对 | 16×? | 只在原始值饱和时用 |

先按 A，用单次采样看 `|top−bottom|`：小于约 3000 就升到 B；接近 16383 或出现 0x3FFF 就降。

### 4.3 按下的方向（0x32 bit6 / bit7）

- Lina 的 H5 固件对原始值做 `16383 - raw`，说明**按下时原始值变小** → H6 应设 bit6=0。
- bit7 是“磁场极性反转”，与磁铁朝向有关，默认 0；如果实测按下时数值反而变大，先改 bit6，仍不对再动 bit7。
- XENO 用 bit6=1（它们的磁铁/结构相反），**不能照抄**。

### 4.4 要不要用 XENO 的未公开寄存器

XENO 还写了 `0x13=0x7F、0x15=0x05、0x16=0x02、0x18=0x03、0x1C=0xFF、0x1E=0x80、0x20=0x80、0x25=0x29`，这些地址在 H6 手册里没有定义。

- 建议**第一轮不写**：先证明“手册公开的最小配置”能工作；
- 如果原始值噪声大、零点偏、或两侧幅度不对称，再把这一组整体加上做 A/B（它们是厂商参考工程的值，很可能就是模拟前端的 trim）。

## 5. 写入顺序与验证

顺序（每项一次写事务：32 clocks 帧 + 39 µs 命令）：

```
0x0C → 0x09 → 0x0B → 0x29 → 0x2A → 0x0F → 0x10 → 0x32 → 0x33(最后)
```

`0x33` 必须最后写，因为它一开就进入连续转换，前面所有参数必须已就位。

写完读回核对（一次性验证代码，测完删）：

| 寄存器 | 期望 | 意义 |
| --- | ---: | --- |
| 0x0C | 0x83 | 与上电默认 0xAA 不同，证明写路径生效 |
| 0x0B | 0x88 | 增益生效 |
| 0x0F/0x10 | 0x1F/0x20 | 间隔生效 |
| 0x32 | 0x01 | 极性/模式生效 |
| 0x33 | 0x80 | 连续转换已开 |

然后立刻做一次连续采样（td1 传 3、td2 传 5），确认返回的是会随按压变化的 14 位原始值。

## 6. 风险

1. **0x0C 必须写 0x83**：默认 0xAA 下芯片行为未定义，漏写可能表现为采样异常；
2. **0x09 bit5 与 0x0B 必须一致**：选了 24× 却忘了 bit5，实际会变成 16×；
3. **0x29/0x2A 必须随 LNA 联动**：手册与 XENO 都强调这一点，写错会改变模拟前端线性度；
4. **0x33 最后写**：提前打开连续转换会让后续配置在转换进行中被写入；
5. 增益选大导致饱和时，原始值会顶在 0x3FFF 附近且按压不再变化——这与“磁铁没对准”表现相似，先看数值是否卡死再判断。
